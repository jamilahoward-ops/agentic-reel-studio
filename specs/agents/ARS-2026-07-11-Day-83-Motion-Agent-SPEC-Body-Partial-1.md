## §6 — 11-Check Self-QC List (LOCKED-as-drafted Day 83)

The Motion Agent runs this 11-check list **on its own motion conform spec** before emitting `successMotionSpec` (or before finalizing an `errorEnvelope`). Check shape inherited verbatim from the fleet §6 pattern (proven 11× — Brief through Sound; Motion is the 12th defense-in-depth firewall pass). Failure semantics are LOCKED inheritance: retry once on a recoverable self-QC failure, halt on the second.

**Critical distinction — self-QC vs. the finish loop:** The **11-step finish loop (§5, outline)** is the agent authoring the *motion conform spec* from the v2 edit + audio spec + EDL typography source; the **§6 self-QC list (this section)** is the agent adjudicating *its own motion spec* — confirming the spec it is about to emit is EDL-faithful, brand-token-faithful, typography-style-faithful, marker-in-timeline, firewall-clean on the passthrough typography it burns in, and free of the operator/finish-impersonation anti-pattern, before that spec becomes the motion-graphics app's (and full QC's) source of truth. A FAIL in §6 means the agent built a malformed finish spec, not that the cut or the mix failed. The creative verdict (`plan_ready`) was Edit Director's; the conform verdict (`edl_ready`) was Editor's; the audio verdict (`audio_ready`) was Sound's; the §6 result decides whether the motion spec is fit to ship to the finish queue.

**QC retry policy (inherited, LOCKED):** First self-QC failure → regenerate the offending motion-spec field set with concrete fix instructions inlined into the next attempt. Second self-QC failure → emit `errorEnvelope` with `failure_code: "motion_agent_failed"`, `attempts == 2`, halt. **No third attempt.** Same 2-strike contract every agent in the pipeline honors.

**Defense-in-depth (12th pass — the TYPOGRAPHY-domain passthrough layer):** The prior eleven passes scanned text the pipeline received, authored (Edit Director, 9th pass), committed to the executable cut spec (Editor, 10th pass), or finished into the mastered audio (Sound, 11th pass). Motion authors **no new copy** — the caption / lower-third / end-card text is Editor/EDL passthrough. But Motion is the agent that **BURNS THE TEXT INTO THE PICTURE** — the moment on-screen typography becomes pixels in the v3 master — so it re-scans the declared caption / lower-third / end-card text one final time before the master reaches full QC. This is **not a new authorship surface** — it is a **passthrough-integrity + typography-finish** re-scan, the **last VISUAL-TEXT checkpoint before full QC**. Because Motion calls **no generative engine, renders no graphics, and decodes no frame**, a self-QC failure here never wastes spend — but a *missed* failure (a banned-entity token that survived the 10th commit pass, sits in a caption or a lower-third, and is burned into the v3 master) is the exact defect class the 12th pass exists to prevent. A leak that survives the finish rides into the delivered picture.

### 6.2 Check ordering rationale

Checks 1–2 are **gate-entry validations** (run FIRST — a failed Sound precondition or a consumed `errorEnvelope` halts before any motion spec is authored; no point finishing the graphics on a reel whose audio never passed). Checks 3–9 are **the seven finish adjudications** (evidence + handle/text resolution, marker-in-timeline, motion-token + reveal-cadence enforcement, typography-style enforcement, author-a-spec-never-render, typography-domain firewall, motion-conform completeness — the substance of the finish decision). Check 10 is **the forensic gate** (lineage — the path that defers to forensic review rather than rendering a verdict). Check 11 is **the construction-integrity gate** (output shape + evidence hash + mode-blind self-attestation + motion_processed-false + recommend-don't-render — it confirms the motion spec is fit to become the motion-graphics app's and full QC's source of truth).

This ordering mirrors the proven 4-tier fleet shape (entry / substance / deferral / handoff), with Motion's defining adaptation: **because the agent spends ~$0.00, decodes no frame, and renders no graphics, the ordering minimizes wasted finish** (fail fast on an unfinished-audio payload) and guarantees the recommend-don't-render discipline (Check 11) is the LAST thing verified before emission, so a malformed `motion_ready` — a motion spec with a firewall leak in a burned-in caption, an all-caps lower-third, a banned motion token, an out-of-range reveal, or a `motion_processed: true` forgery — can never escape.

**Pattern parity with Sound §6.2 / Editor §6.2 / Ingest §6.2:** identical 4-tier conceptual ordering. Cross-SPEC consistency invariant. **Motion's adaptation is that it carries TWO brand-policy adjudications where Sound carried one.** Sound's single brand-policy surface was loudness (a platform const). Motion's domain has two structurally distinct brand-policy surfaces — **motion behavior** (Check #5: the token set, the ease/bounce policy, the reveal cadence) and **typographic style** (Check #6: lowercase-sans lower-thirds, one-line captions, the serif-ivory end-card) — which fail differently, are fixed differently, and therefore adjudicate separately. That split is the §6.3 cardinality justification below. As in Sound, the **firewall pass (Check #8) runs AFTER the specification steps in the §5 loop** (Steps 6–7 author the reveals, placements, overlays, and end-card; Step 8 re-runs the firewall over the typography the finish burns in) — but in the §6 self-QC list it is sequenced among the substance adjudications because by self-QC time all specifying is complete. The contrast with Sound: its 11th pass scanned the spoken text the agent *finishes into the audio*; Motion's 12th pass scans the on-screen text the agent *burns into the picture* (typography-domain passthrough integrity, the last visual net before full QC).
