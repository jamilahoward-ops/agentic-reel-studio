### 9.1 Fixture-economy rationale (surfaced)

The unexercised codes are all either **deterministic entry/forensic halts** (`upstream_audio_not_ready`, `upstream_not_success`, `motion_lineage_failure` — single equality/shape assertions, behaviorally trivial, schema-enforced, identical in mechanism to the fleet's proven entry-gate fixtures) or **substance codes whose mechanic is fully covered by a sibling behavioral fixture or by the type system itself**:

- `text_asset_unresolved` shares TC-04's resolution machinery — it is the **named optional runbook probe**, chosen precisely to demonstrate the SPLIT-code distinct-route path (→ Editor, not → Sound).
- `motion_token_out_of_spec` and `typography_out_of_spec` are the two **type-layer-enforced** codes: the banned motion tokens are made unrepresentable by `enum` on `motion_tokens.applied[]`, and the all-caps lower-third is made unrepresentable by `const: false` on `lower_thirds[*].all_caps` (§10.4). **A malformed spec carrying either defect cannot serialize against the output schema** — so their primary test is a *schema-negative* fixture (assert the validator REJECTS the payload), not a behavioral run. The behavioral surfaces that the type system cannot catch — the **reveal-cadence collision** (two reveals <8000ms apart, an interval assertion the schema cannot express) and the **end-card text drift** — are the two named runbook probes for this family.
- `spec_fidelity_breach` shares TC-01's dual-hash-verify machinery (a tampered `edl_evidence_hash` or `audio_spec_evidence_hash`); the caption-text-drift variant is the third runbook probe.

Spending fixture slots on them would displace the two clean-MOTION_READY convergence proofs (TC-01/TC-02) and the three highest-stakes Motion-original surfaces — the two principal route-backs (TC-03 → Editor, TC-04 → Sound) and TC-05 (the typography-domain firewall, the last visual-text line before the master) — that no other test can provide.

**There is NO `revise` verdict to exercise** — Motion's two-verdict determinism (D3) means the only outcomes are `motion_ready` and `fail`, both covered. This is the divergence from Edit Director's §9, which reserved a runbook adversarial case for its one `revise` judgment surface; Motion has none (it inherits the Editor + Sound posture). Slot-11 (`motion_agent_failed`) is definitionally un-fixturable from outside (it requires inducing the agent to build a malformed motion spec twice); the runbook's adversarial case covers its semantics, including the two forgery variants it catches (a `motion_processed: true` claim and a mode-blind violation). Same economy Sound ratified at Day 76, Editor at Day 68, Edit Director at Day 60, Ingest at Day 52, QC Pre-flight at Day 43.

### 11.2 Faithful-finish value model (the economic justification)

Motion produces no margin directly. Its value is **brand-faithful, entity-safe, first-pass typography + motion finish + downstream-cost prevention**, quantified across the defect classes it uniquely prevents:

## §12 — Verdict Math (LOCKED-as-drafted Day 85)

### 12.1 The ∧-of-gates composition (NO judgment slot — fully deterministic)

Deterministic boolean composition over declared evidence — **no thresholds, no weights, no scores, and NO subjective branch.** This is the defining inheritance from Editor's and Sound's §12 (both of which carved out zero judgment slots): Motion is a faithful executor, so the success-side is a pure conjunction with zero judgment surfaces.

```
MOTION_READY = (sound_precondition_met)            # Check 1  — audio verdict == "audio_ready" ∧ output_type == "successAudioSpec"
             ∧ (upstream_success)                   # Check 2  — no errorEnvelope branch consumed
             ∧ (audio_spec_evidence_hash_verified)  # Check 3  — SHA-256 recomputes (audio spec not tampered post-finish)
             ∧ (edl_evidence_hash_verified)         # Check 3  — SHA-256 recomputes (EDL not tampered post-conform)
             ∧ (v2_edit_resolved)                   # Check 3  — finish_target.v2_edit_uri resolves (the audio-final picture)
             ∧ (all_text_fields_resolved)           # Check 3  — every caption / lower-third / end-card text present + non-empty
             ∧ (all_markers_in_timeline)            # Check 4  — every reveal/overlay/lower-third/end-card 0 ≤ at_ms ≤ total_timeline_ms
             ∧ (motion_tokens_in_brand_set)         # Check 5  — applied[] ⊆ {slow_push_in, static_hold, subtle_parallax}; ease + bounce = brand const
             ∧ (reveal_cadence_in_spec)             # Check 5  — one line at a time ∧ ∀i: at_ms[i+1] − at_ms[i] ≥ 8000
             ∧ (typography_style_in_spec)           # Check 6  — lower-thirds lowercase-sans-left-underline ∧ ¬all_caps; captions one-line; end-card = brand const
             ∧ (duration_in_band)                   # Check 9  — 45000 ≤ total_timeline_ms ≤ 75000 (re-assert from the EDL)
             ∧ (spec_fidelity_edl_faithful)         # Check 9  — caption ∧ lower-third ∧ end-card text byte-faithful ∧ duration matches EDL
             ∧ (motion_firewall_clean)              # Check 8  — 12th-pass typography hits == 0 (∧ consistent with motion_self_check.banned_vocab_hits)
             ∧ (mode_blind)                         # Check 7  — production_mode_read == false
             ∧ (lineage_intact)                     # Check 10 — well-formed inbound 10-tuple + valid 11-tuple extension
```

### 12.2 Non-ready routing (the verdict function — TWO outcomes only)

Any single ∧-term false → the verdict function routes per the §6.3 / §3.2 map. **There is NO `revise` branch — every non-ready outcome is a halt or a fail.** This is the two-verdict model (D3):

```
# Halts (entry / forensic / construction gates)
if ¬sound_precondition_met         → halt  upstream_audio_not_ready
if ¬upstream_success               → halt  upstream_not_success
if ¬lineage_intact                 → halt  motion_lineage_failure        (forensic)
if ¬mode_blind                     → halt  motion_agent_failed           (slot-11 — agent read production_mode)

# Fails (substance adjudications)
if ¬v2_edit_resolved               → fail  v2_edit_unresolved            (route_back: sound-agent)
if ¬all_text_fields_resolved       → fail  text_asset_unresolved         (route_back: editor-agent)
if ¬all_markers_in_timeline        → fail  motion_marker_out_of_range    (route_back: editor-agent)
if ¬motion_tokens_in_brand_set     → fail  motion_token_out_of_spec      (route_back: editor-agent · detail names the token)
if ¬reveal_cadence_in_spec         → fail  motion_token_out_of_spec      (route_back: editor-agent · detail names the colliding pair)
if ¬typography_style_in_spec       → fail  typography_out_of_spec        (route_back: editor-agent · detail names the element)
if ¬audio_spec_evidence_hash_verified → fail  spec_fidelity_breach       (tampered audio spec — route_back: sound-agent)
if ¬edl_evidence_hash_verified     → fail  spec_fidelity_breach          (tampered EDL — route_back: editor-agent)
if ¬spec_fidelity_edl_faithful     → fail  spec_fidelity_breach          (forensic log + deviating field named)
if ¬motion_firewall_clean          → fail  motion_firewall_breach        (forensic hold + typography field named · route_back: null)
```

**Precedence:** halts (entry / forensic / mode gates) adjudicate before fails; among fails, the FIRST failing check in §6.2 tier order names the headline `failure_code`, with all computed evidence still emitted (no short-circuit nulls — every sub-status explicitly dispositioned regardless of the headline). **There is no `revise` precedence rung — the verdict space is exactly `{motion_ready, fail}` with halts being a fail sub-class that does not route back for re-work.**

**The one route-back asymmetry worth naming (surfaced):** `spec_fidelity_breach` is the only code that routes to **two different agents** depending on *which* hash failed (`audio_spec_evidence_hash` → Sound; `edl_evidence_hash` → Editor). This is a consequence of Motion being the first agent to consume **two** independently-hashed upstream artifacts. The `detail.tampered_artifact` field names which — the schema author encodes `route_back_to` as a computed field, not a per-code const (§10.4).

### 12.3 Properties (why this is the right math for a faithful executor)

1. **Fully deterministic** — same inputs, same verdict, every run, for EVERY term. There is no soft surface, no gradient, no judgment slot. The LLM is constructing + attesting, never judging. This is the strongest determinism posture in the fleet (Ingest/Editor/Sound-class, transplanted to the typography/motion-graphics seam).
2. **Monotone** — adding a defect can never improve the verdict. There is no compensatory scoring where a clean reveal cadence offsets a banned `whip_pan`, an all-caps lower-third, or a firewall hit in a burned-in caption.
3. **Zero-false-motion-ready by construction** — `motion_ready` requires EVERY term true; ambiguity biases to `fail` (Hard Rule #13). The 0% false-motion-ready target (§8.7) is a property of the composition, not a tuned threshold.
4. **Two of the fifteen ∧-terms are enforced in the TYPE SYSTEM, not just the composition** — `motion_tokens_in_brand_set` (partially: the banned tokens are `enum`-excluded) and `typography_style_in_spec` (partially: `all_caps` is `const: false`). A spec that violates them **cannot serialize**. This is the strongest brand-policy encoding in the fleet: the verdict math is the second line of defense, not the first. *(The interval assertions — reveal cadence, marker-in-timeline — remain composition-only; JSON Schema cannot express "consecutive elements ≥8000ms apart.")*
5. **NO judgment slot — inherited from Editor + Sound** — where Edit Director isolated exactly one `revise` branch for a soft brand-rule tension, Motion has ZERO (as Editor and Sound do). A `revise` here would mean second-guessing a locked cut AND a finished mix — exactly the double override the finish/finish boundary forbids (D3). Human deferral lives entirely in `human_review_required: true` + `finish_mode: "human_in_the_loop"` + `motion_processed: false` on EVERY emission (recommend-don't-render), not in a verdict branch.
6. **Auditable** — the emitted motion spec carries the evidence for every term (§10 per-check evidence rows), so any verdict is recomputable by a human from the motion spec alone. Recommend-don't-render depends on exactly this recomputability.

**Divergence from Edit Director's ∧-plus-revise (surfaced):** Edit Director's domain is partly creative — mostly deterministic but with ONE genuine judgment surface, so it carried `revise` exactly where QC Pre-flight carried `hold`. Motion's domain is **fully deterministic** (a token is in the brand set or it isn't; a lower-third is lowercase-sans or it's an all-caps screamer; a reveal is inside the timeline or it isn't; two reveals are 8s apart or they collide; the typography is byte-faithful or it's an override; the firewall is clean or it isn't) — so it carries NEITHER. Motion is `motion_ready | fail`, full stop — the same binary determinism Editor, Ingest, and Sound hold, transplanted to the typography/motion-graphics seam. The judgment slot belongs upstream where the creativity is; the executor downstream is deterministic by design.
